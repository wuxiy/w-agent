# 本地优先的 AI Agent 工具集 · by 小傅哥 xiaofuge

agent-os

三个独立又互联的子项目：WaLiAPI 把 API Key、免费、OAuth 账号三类渠道统一成一个多协议网关； walicode 在服务端跑完整的 ReAct 引擎，替你编码和运维； walissh 让 SSH 终端听得懂人话。AI 在服务端思考，权限在你手里。

$ git clone --recursive https://github.com/wuxiy/agent-os.git
agent@walicode — chat_stream (SSE)

三个子项目，各司其职

每个子项目都是独立 git 仓库、独立演进；通过 git submodule 聚合在本工作区，可单独拉取更新。

FLAGSHIP

walicode

AI Coding + DevOps 工作台

Agent 的大脑住在 Spring Boot 服务端：双层意图识别（规则 + LLM）、任务拆解、 上下文裁剪与压缩、核心记忆。Tauri 客户端只是壳——连你本机的命令， 也是服务端通过反向通道（127.0.0.1:17890）请求执行，且必须经你点确认。

  • ReAct 节点链 + 策略树多线程路由
  • PermissionGuard 危险操作人工确认
  • MCP / Skills / 声明式 Agent 装配（改 YAML 不改 Java）
  • core_memory 长期记忆：记住你的纠正与偏好

# agent/code-agent.yml — Agent 声明式装配

agent:
  name: code-agent
  model: gpt-4o # 经 WaLiAPI 路由
  tools: [ssh_exec, sftp, local_exec, mcp]
  reactBudget:
    contextTokenBudget: 8000
    maxRounds: 12
  permission: confirm-on-danger
GATEWAY

WaLiAPI

本地 LLM API 网关 · 127.0.0.1:8777

一个自生成的 sk-waliapi-* 密钥，接入 API Key、免费（OpenCode/Kilo 开箱即用）、 OAuth 账号（Codex/Kimi/Antigravity 等）三类上游渠道。 内嵌 Axum 服务对外暴露 OpenAI、Anthropic、Responses 三套协议端点， 渠道按优先级 + 权重调度，失败自动切换；敏感信息在出网关前完成扫描、脱敏或阻断； 内置 RAG 知识库与 LLM-Wiki，经 /mcp、/api/kb 提供给 Agent 检索。

walissh

AI 驱动的智能 SSH 运维终端

walicode 的前身，保留了最纯粹的一条链路：xterm.js 终端 + SFTP 文件管理 + AI 运维助手。SSH 密码以 AES-256-GCM 加密落库，连接与命令全部在服务端执行。 想看这套架构最小可行形态，读它。

  • 终端走 HTTP 轮询模型，无 WebSocket 依赖
  • 双层意图识别：指代消解后直连目标机
  • 代码、配置、SQL 中仍可见 walicode 的演进痕迹

ReAct 引擎：思考、行动、观察、再思考

不是一次 LLM 调用，而是一条可循环、可压缩上下文、可被人打断的节点链。

RootNode 建会话·载历史 ──▶ AiCallNode 调模型 ──▶ ToolCallNode 执行工具 ──▶ LoopDecisionNode 继续? ──▶ UserFeedbackNode 输出

↺ 未完成任务回到 AiCallNode 继续循环 · 危险工具调用在 ToolCallNode 挂起，等待 PermissionConfirmManager 人工确认 · 上下文超预算时 ContextCompressor 四级降级（优先级裁剪 → 滑动窗口 → AI 摘要 → 兜底）

五分钟跑起来

一个脚本完成依赖检查、子模块、中间件、建库导数、服务端与客户端启动。

quick-start.sh
